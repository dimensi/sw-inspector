Не запускать две модели одновременно на `App.svelte`, `expressions.ts` или общих типах в одном checkout.

## Как выдавать задачу небольшой модели

Передать один ID задачи, а не весь roadmap. Пример готового задания:

> Выполни только C1 из `docs/plans/2026-10-19-01-cache-deletion.md`. Сначала прочитай AGENTS.md, PRODUCT.md, DESIGN.md, ADR 0002, общий design и секцию контрактов плана 00. Убедись, что зависимости C1 уже реализованы. Соблюдай интерфейсы из плана. Напиши указанные поведенческие тесты и проверь их падение до реализации. Не реализуй C2/C3, не расширяй permissions, не меняй архитектуру relay и не трогай чужие изменения. При несовпадении исходников с предпосылками опиши конкретное расхождение, не придумывай совместимость. В конце перечисли изменения, фактически выполненные проверки и оставшиеся native Safari checks. Не коммить и не публикуй без отдельного указания.

Для любой задачи заменить C1/имя плана. Перед передачей следующей задачи проверить diff и результаты предыдущей. Для общего фундамента, destructive actions и messaging нужен отдельный review контрактов, навигационных гонок и native Safari результата; это не компенсируется количеством зелёных unit-тестов.

**Стоп-условия исполнителя:** требуется новый host permission, прямой panel eval, background/content script, обход CORS/CSP, изменение публичного контракта соседней задачи или недоступное в Safari API. Зафиксировать минимальный воспроизводимый факт и вернуть вопрос владельцу плана. Отсутствие native GUI не мешает закончить код/тесты, но native acceptance остаётся открытой и не считается выполненной.

## Что ещё полезно

| Приоритет | Идея и отдельная небольшая задача | Проверяемая граница |
| --- | --- | --- |
| Следом за 02/04 | **Журнал lifecycle:** updatefound, statechange, controllerchange с временем и ссылкой на регистрацию | Использовать ограниченную сессию/lease из сообщений; только наблюдавшиеся события. Не объявлять polling полной историей браузера. Тесты: заменённый worker, stop/restart, overflow, navigation |
| Следом за 01 | **Сравнение двух снимков кеша:** добавленные/исчезнувшие ключи и изменения прочитанных metadata | Новый чистый `src/cache/diff.ts` и `tests/cache/diff.test.ts`; обе выборки одной origin. URL+method+Vary metadata нужны для сопоставления; неоднозначные дубликаты = ambiguous, неполный снимок не доказывает удаление. Без автоматического чтения тел и без SHA всей базы |
| Следом за 03 | **Просмотр одной manifest icon:** реальное разрешение против declared sizes | Отдельная явная загрузка ≤1 MiB, 8 s, page-context CORS, PNG/JPEG/WebP; локальный Blob URL и revoke. SVG сначала только metadata. Ошибка чтения не означает, что Safari не умеет показать иконку |
| Позже | **Копирование диагностического отчёта для багрепорта** с выбором разделов и удалением query/hash из URL по умолчанию | Новый opt-in формат, стабильный version, preview перед сохранением. Удаление query/hash не равно полной анонимизации; не включать тела, сообщения, raw manifest и headers по умолчанию |

Не включать пока: «полностью очистить данные сайта», редактирование кешированных ответов, произвольный JS-console, синтетические push/sync, bypass SW/offline переключатель, force stop/start, автоматический SKIP_WAITING. Это отдельные продукты/привилегии либо site-specific протоколы, а не продолжение текущего набора API.

## Готовность и обслуживание документов

- В каждом плане checkbox изначально пуст. Отмечать только проверенный результат.
- При реализации первого изменения границы read-only принять [ADR 0004](../adr/0004-explicit-development-actions.md) и обновить PRODUCT/AGENTS/copy одновременно с функцией. ADR принят для C1 selected namespace, C2 fixed-list batch deletion и C3 retained-request entry deletion; остальные исключения ещё не активированы.
- Записывать реальный Safari результат в [TESTING.md](../TESTING.md): версия, installation route, origin, действие, результат. Синтетическая fixture и WebKit Playwright — отдельные доказательства.
- После выпуска перенести устойчивые решения в владельцев фактов (PRODUCT/DESIGN/ADR/TESTING). Выполненный план удалить либо убрать из актуального индекса; не оставлять два противоречащих источника требований.
